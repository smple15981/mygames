# Hearthwild HD-2D 设计规格

日期：2026-08-04  
状态：等待用户最终评审  
目标引擎：Godot 4.x  
工作分支：`design/hd2d-foundation`

## 1. 产品定位

Hearthwild HD-2D 是一款原创俯视角生活冒险动作游戏。它不会直接复刻《我的世界》《泰拉瑞亚》《星露谷物语》或《DNF》的角色、世界观、关卡与界面，而是提取四类核心体验并重新组合：

- 沙盒游戏：采集、制作、基地布置和有限地形改造。
- 生活模拟：种植、经营、时间推进、NPC 委托和家园成长。
- 探索冒险：森林、洞穴、遗迹、资源层级和区域首领。
- 动作角色扮演：连击、闪避、技能、装备词条和高反馈打击感。

核心主题：**通过冒险获得资源，通过建设改变世界。**

## 2. 首个垂直切片

首个版本只验证一个 20～30 分钟可重复循环，不制作完整开放世界。

### 2.1 可玩区域

1. 农场基地：房屋、农田、储物箱、工作台、篝火。
2. 森林区域：树木、石头、草药、史莱姆类敌人。
3. 洞穴入口：矿石、精英敌人、首个升级材料。

### 2.2 核心流程

```text
采集木材和石头
→ 制作斧头或武器升级
→ 开垦并种植作物
→ 接受一个简单委托
→ 前往森林战斗
→ 获得洞穴钥匙或特殊材料
→ 击败洞穴入口精英敌人
→ 返回基地升级工作台
```

### 2.3 首版必须实现

- 八方向移动和面向。
- 普通攻击、三段连击、闪避和受击无敌帧。
- 一种近战武器。
- 一种普通敌人和一种精英敌人。
- 木材、石头、植物和矿石采集。
- 12～20 格背包。
- 3～5 个制作配方。
- 土地开垦、播种、浇水和一次作物成长。
- 基础存档与读取。
- 主菜单、暂停菜单、血量和快捷栏 UI。

### 2.4 首版明确不做

- 联机。
- 无限程序化世界。
- 完整四季与天气。
- 大量 NPC 和恋爱系统。
- 多职业和复杂天赋树。
- 随机词条海量装备。
- 自动化流水线。
- 手机端适配。

## 3. 视觉方案：混合 HD-2D

### 3.1 画面结构

- 环境：低多边形 3D 模型、正交摄像机、固定俯视斜角。
- 角色：像素风或低分辨率 2D Sprite3D，看向摄像机并保持像素采样。
- 特效：2D 手绘或像素序列帧，使用 Sprite3D、GPUParticles3D 和轻量 Shader。
- UI：纯 2D 像素风界面。
- 光照：真实 3D 阴影配合低分辨率渲染与轻度色调映射。

### 3.2 摄像机与显示

- 正交摄像机，约 35°～45° 俯角。
- 摄像机不自由旋转，避免 2D 角色出现穿帮。
- 目标基础分辨率为 640×360 或 960×540，再整数或近整数放大。
- 角色与 UI 使用 nearest-neighbor 过滤。
- 3D 环境可使用适度抗锯齿，但保持清晰轮廓。

### 3.3 美术统一规则

现成素材只作为基础原料，导入后统一处理：

- 限制主色数量和饱和度。
- 统一材质粗糙度、阴影强度和轮廓对比。
- 对模型比例进行统一，保证门、角色、树木和道具尺度一致。
- 不混用写实 PBR 与卡通低多边形素材。
- 所有 2D 角色保持一致像素密度、轮廓宽度和动画帧率。

## 4. 开源素材策略

优先采用 CC0 素材，以降低授权风险和商业化限制。

### 4.1 计划素材包

- Kenney Nature Kit：树木、岩石、植物和自然场景模型。
- Kenney Fantasy Town Kit：房屋、围栏、道路和村庄道具。
- Kenney Modular Dungeon Kit：洞穴和遗迹模块。
- Kenney Tiny Town：像素风地表、图标或原型角色参考。
- Kenney Tiny Dungeon：地下城、敌人、道具和 UI 原型素材。
- Kenney UI Pack - Pixel Adventure：菜单、按钮和面板原型。

### 4.2 仓库素材规则

- 每个素材包放入独立目录。
- 保留原始许可证文件和来源说明。
- `THIRD_PARTY_NOTICES.md` 记录素材名称、作者、来源、许可证和用途。
- 不提交来源不明、仅限个人使用或禁止再分发的素材。
- 大体积素材优先只导入实际使用的文件，避免仓库膨胀。
- 后续商业发布前再次逐项审计许可证。

### 5.2 主要组件

#### PlayerController

负责移动、朝向、闪避、输入锁定和状态切换。它不直接处理背包或伤害数值，只发送动作请求。

#### CombatComponent

负责攻击阶段、命中检测、伤害结算、击退、无敌帧和受击反馈。玩家与敌人共用基础接口。

#### InteractionComponent

负责识别可采集资源、农田、工作台、箱子和 NPC，并显示交互提示。

#### InventoryService

负责物品堆叠、移动、增加、消耗和快捷栏。配方与农场系统只通过公开接口访问背包。

#### FarmingSystem

负责土地状态、种子、浇水和作物成长。首版使用离散阶段，不模拟复杂基因或品质。

#### CraftingSystem

从数据资源读取配方，检查材料后调用 InventoryService 原子化扣除和产出。

#### SaveService

负责将玩家位置、背包、农田和关键进度序列化为版本化 JSON 或 Godot Resource。

#### WorldState

记录资源节点是否被采集、精英敌人是否击败以及工作台等级。

## 6. 数据流

### 6.1 采集

```text
玩家输入交互
→ InteractionComponent 获取目标
→ 目标验证工具与距离
→ 资源播放反馈
→ InventoryService 添加产物
→ WorldState 更新节点状态
→ SaveService 在安全节点保存
```

### 6.2 战斗

```text
玩家输入攻击
→ PlayerController 请求攻击状态
→ CombatComponent 生成命中窗口
→ Hurtbox 接收命中信息
→ DamageResolver 计算伤害
→ 目标播放受击、击退或死亡
→ 掉落系统生成物品
```

### 6.3 制作

```text
UI 选择配方
→ CraftingSystem 检查工作台等级
→ InventoryService 验证材料
→ 原子化消耗材料
→ 添加成品
→ UI 刷新并播放反馈
```

## 7. 错误处理和稳定性

- 数据资源加载失败时输出明确错误并跳过非法条目，不让整个游戏崩溃。
- 制作操作必须原子化，避免扣除一半材料。
- 保存前写入临时文件，验证成功后再替换正式存档。
- 存档包含 `save_version`，未来升级时执行迁移。
- 场景切换期间锁定输入，防止重复触发。
- 对缺失贴图或模型提供明显的开发占位物。
- 第三方素材导入失败不阻塞核心逻辑测试。

## 8. 测试策略

### 8.1 自动测试

- 背包堆叠、容量和扣除。
- 配方材料验证和原子化制作。
- 伤害、无敌帧和死亡状态。
- 农作物阶段推进。
- 保存与读取后的数据一致性。

### 8.2 场景测试

- 玩家能否连续移动、攻击、闪避而不锁死。
- 多个敌人同时命中时是否重复受伤。
- 资源节点重复交互是否产生重复掉落。
- 背包满时采集物如何处理。
- 场景切换后玩家位置与世界状态是否正确。

### 8.3 验收标准

- 新玩家不看说明可在 5 分钟内完成第一次采集和制作。
- 20～30 分钟内可完成一次完整循环。
- 普通电脑在 1080p 下保持稳定 60 FPS。
- 不存在阻断流程的脚本错误。
- 项目可由干净环境克隆后直接在指定 Godot 版本打开。

## 9. 开发阶段

### 阶段 0：工程基础

- 初始化 Godot 项目、目录、输入映射和基础 CI。
- 建立许可证和第三方素材登记制度。

### 阶段 1：可移动的 HD-2D 场景

- 正交摄像机。
- 3D 环境原型。
- 2D Sprite3D 玩家。
- 移动、碰撞和深度排序验证。

### 阶段 2：战斗切片

- 三段普攻、闪避、受击。
- 普通敌人、精英敌人、掉落。

### 阶段 3：采集、背包与制作

- 资源节点。
- 背包与快捷栏。
- 工作台与配方。

### 阶段 4：农场与进度闭环

- 土地、播种、浇水、收获。
- 精英掉落升级工作台。
- 基础任务与通关提示。

### 阶段 5：打磨

- 光照、Shader、音效、反馈、性能和自动测试。
- Windows 可执行版本。

## 10. 关键决策

- 首版采用 Godot 4.x 和 GDScript。
- 采用 3D 环境 + 2D 角色的真正混合 HD-2D，而不是仅给纯 2D 地图增加光照。
- 摄像机固定，优先保证美术一致性和战斗可读性。
- 首版单机、单地图、单武器、少量敌人。
- 优先使用 CC0 素材，并保留完整第三方声明。
- 完成垂直切片后再决定联机、程序生成和职业系统。

## 11. 规格自检

- 未保留 TBD、TODO 或未决核心功能。
- 首版范围可由单一实现计划覆盖。
- 玩法循环、组件边界和开发阶段相互一致。
- 素材许可、存档稳定性和测试要求已明确。
